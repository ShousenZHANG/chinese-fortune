# 奇门遁甲：排盘与解释范围

先按[输出契约](22-output-contract.md)回答问题。默认 `--plate-method yuanling-core` 输出已核地盘、值符原星与落宫、值使九宫计数。其余格子留空，表示尚未核定，不表示没有星门。要全盘和格局，显式用 `--plate-method dunjia-zhuanpan`：按《遁甲演义》转盘排，格局照该书卷二原文判，每条都与书中例题对照过；它与元灵经不是同一部书，`source_core` 仍单列元灵经结果。旧全盘只有显式 `--plate-method rotating-compat` 才输出，不判格局，不能与 `source_core` 拼成同一盘。完整规格及原例见[方法说明](../docs/QIMEN-LIUREN-METHODS.md)。

## 起盘

先取得用户当前所在地时间。目标时刻、目标地点与用户当前所在地分开；已有完整时间不要重复询问。例：

```bash
python scripts/qimen_cast.py --date 2026-06-18 --time 08:00 --target-timezone Asia/Shanghai
```

默认 `--ju-method futou`：按目标有效日期取得最近甲或己符头，子午卯酉为上元、寅申巳亥为中元、辰戌丑未为下元，再按实际已交节气选局。交节不重置五日符头组，且不置闰。不能把任何甲己日都当上元。

有时区时用实际瞬间比较交节；没有时区的历史钟面输入是 `floating_calendar_assumption`，节气交界无法确认唯一盘。应补目标时区，不宣称自动用了用户所在地。经度修正只改变有效当地日时，不改变实际交节瞬间。

`--ju-method legacy-days` 是旧版简化日数法，仅用于结果对比，不是默认古法。手動排局同时给 `--ju-type yang|yin` 和 `--ju-number 1..9`，并说明局由用户指定。

## 基础盘面

三奇为乙、丙、丁；六仪戊己庚辛壬癸依次对应甲子、甲戌、甲申、甲午、甲辰、甲寅。天干甲藏在该旬六仪下。阳遁从局数宫顺布戊己庚辛壬癸丁丙乙，阴遁逆布。

## 如何读输出

先解释确定结构。例如“这盘为阳遁九局，值使死门落七宫”只是计算位置；“死门”是传统门名，不等于死亡、危险或事情失败。门、星、神的名称不能单独证明事件结果。

`patterns` 只在 `dunjia-zhuanpan` 下有内容，分七类：九遁、吉格、诈假、十干凶格、时日凶格、伏吟反吟、门迫。每条带 `passage_id` 和照录原字的 `quote`；`variant: true` 是原文「又曰」「一云」的并列说法，和正条分开说。`kind` 只转述原文给的吉凶方向，不是总评，也不能套出成功、发财、疾病或第三方行为。原文写不清的条目（人假、三奇受制、天网四张，以及依月将贵人的天三门地四户等）列在 `patterns_not_computed`，不能说「没有这些格局」。旧兼容盘的格局判定已删除：它把青龙返首和飞鸟跌穴颠倒，三诈、五不遇时等条件也与原文不合。

本版已移除 `auspicious_directions`、`inauspicious_directions` 和星门奇仪加减分。不得按“吉门加二、吉星加一”重新拼一个方位排名。宫位的北、东南等仅为盘面方向；不能据此确认失物所在、失踪者位置或治疗方向。

资料齐全时可以完成当前支持的结构说明：说明节气与符头、遁局、值符值使如何得到、相关宫位和门星神。个人问题要进一步取用时，另查对应原文及适用条件，标出主本与分歧；不能把古籍的历史占辞视为现实事实，也不能仅用一段笼统提醒代替可完成的计算解释。

## 奇门择时

用户要在一段日子里挑时辰，用：

```bash
python scripts/qimen_select.py --from 2026-11-02 --days 3 --target-timezone Asia/Shanghai
```

逐时辰排遁甲演义转盘。候选要有九遁、吉格或诈假的正条；五不遇时、三奇入墓、时干入墓、六仪击刑、伏吟反吟整个时辰不用；吉格所在宫门迫的不算；本宫兼成凶格的保留，标 `flaw`。三奇得使兼成青龙逃走、荧入太白、朱雀投江时，原文说「如遇本旬直符同臨其上方可用之而吉也」：本旬直符不同临就不算吉格，只剩这一条吉格的时辰不进候选。每条规则都写了出处（`rules`）。候选按时间先后列，彼此不分高下，回答时不要自己排名次。它不看个人八字；用户有八字或具体事项时，说明这只是时辰本身的格局筛选。最多 31 天。

日期按目标 IANA 时区解释，覆盖早子和23点至午夜的晚子。时辰、交节和 offset 变化处拆为左闭右开的实际区间，每段按起点排盘。用 `start`、`end`、`sampled_at` 的完整 ISO 时刻及 offset 回答，`window` 只供显示；重复钟点保留两次，不存在的钟点不编造，跳日见 `skipped_dates`。`candidates` 与 `excluded_windows` 共同覆盖请求，排除计数按分段区间计。与单次起盘对照时显式给 `--plate-method dunjia-zhuanpan --ju-method futou`，默认元灵经核心不变。

## 核验依据

《奇门遁甲元灵经》卷一，[固定转录版本 8259389](https://zh.wikisource.org/w/index.php?oldid=8259389)。核验限所列章节与原例，未做原刻影像校勘，不声明整个奇门引擎已经完整验证。

`dunjia-zhuanpan` 与格局依据四库本《遁甲演义》卷一（dunjia:c001:p0007 中五寄坤）、卷二各格局条。31 条书中例题逐条复算一致；另有两条原文例与本书其余各例的转法不合（p0035 甲申日伏干例、p0009 阴三局「乙奇在杜门」），已在测试里记明，不作夹具。

## 定局：拆补与置闰

默认 `--ju-method futou`：按实交节定节气、符头（甲、己日）地支定上中下元，即拆补法，节气一到就换局。`--ju-method zhirun` 改用《遁甲演义》卷一的超神接气置闰（dunjia:c001:p0013–p0015）：每个节气配一个上元符头起的十五日，按符头连排；符头早于交节为超神、晚于为接气、同日为正授；只在芒种、大雪，上元符头比交节早九日以上时再排一次同一节气（闰奇）。书中万历二十六年大雪超十二日置闰、二十七年小暑甲子正授、二十九年芒种超九日置闰、二十六年芒种超八日不闰，测试逐条复算。输出在 `method_profile.solar_term` 写明 `mode`、`chao_days`、`yuan_start`。两法在超神、接气、闰奇的日子定局不同，回答写明用的是哪一法；茅山法、飞盘没有随包原文，不提供。置闰目前只接默认地盘，`dunjia-zhuanpan` 全盘仍用拆补。
