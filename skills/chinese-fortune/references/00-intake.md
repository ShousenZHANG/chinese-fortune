# 输入与时间

先提取已有资料，再一次问清影响计算的缺项。纯八字不需要姓名、曾用名或在世状态；不要求用户重复已明确的信息。

## 当前时间

本题依赖“现在”时才确定当前所在地时区；纯原局、术语解释与明确参考年份不因此补问现居地。对话中已明确就复用；确实需要却未知时询问城市或 IANA 时区，不用出生地、电脑时区或猜测的 IP 地址代替。电脑时区只能用来措辞确认，用户确认后才算数。等待期间仍可核不依赖当前时间的原局；相对当前的岁运保持未定。

调用 scripts/request_time.py --current-timezone Australia/Sydney。取得一次 UTC 时刻和当地表示，同请求后续工具复用 --request-time、--current-timezone。

个人未来时段也可直接用 `fortune_reading.py --stdin`：它在计算前取时一次。若本请求已经取过时间，传入同一个 `request_time`，不用再取一次。自然时间范围、候选档期、多人和档案字段见 [专用流程](24-personalized-forecast.md)。

- 出生时间：出生当天的当地钟表时间、出生地及历史时区。
- 当前时间：现在位于哪里，用于“今天”“今年”与岁运参照。
- 目标时间：用户明确问的历史或未来时刻，优先于“现在”；目标地点可不同。

只给目标日期时，黄历日级查询可执行；时家起盘还需时分，不拼入当前时分或默认午时。公历年度和命理立春年界分别处理。

## 生辰资料

| 字段 | 处理 |
|---|---|
| 出生年月日 | 明确公历或农历；农历遇闰月须确认。只需换算日期时用 `scripts/lunar_convert.py solar2lunar|lunar2solar`，不必排盘 |
| 出生时分 | 已知则使用；未知保留可固定的柱，日界或交节日还可能影响年、月、日柱；紫微需时辰 |
| 性别口径 | 用于传统大运顺逆等计算，按用户提供的字段传入 |
| 出生地 | 用 --city 查城市表；未收录时取得真实经度和 IANA 出生时区 |
| 问题 | 先回答最相关的一项，用户要求全面再展开 |

资料冲突或可能改变时柱时才确认。正常完整输入直接计算，在结果中简要回显采用资料。

## 边界

- 海外与历史夏令时：按出生日期解析出生地时区，不手工重复减夏令时。
- 不存在的当地时间：解释跳时空档，要求更正。
- 重复的当地时间：说明两次对应的 offset，用 --fold 0/1 选择。
- 时辰区间：分别核算候选盘；共同部分先说，变化部分明确指出。
- 未知时辰：内部午时仅供日历换算，占位不进入时柱或个人解释。
- 夜子时：明确采用子初或子正换日，不在正文偷换口径。
- 真太阳时：八字、紫微默认使用出生经度和当日均时差；钟表口径传 --time-standard clock。其他方法依对应条款确定。
- 节气边界：按精确时刻判断年柱和月柱；时分未知且可能跨界时保留候选。

## 展示与保存

正文只展示与问题相关的盘面。完整四柱、藏干、纳音、十神、月令、大运、流年、时间修正可按需展开。旺衰分数属于工程诊断；用神、喜忌、格局候选须另核条款。

## 数据处理声明

出生时间拿不准且可能跨日期（「5 号深夜还是 6 号凌晨」）或给出几个互不相连的时刻时，用 `scripts/birth_candidates.py --stdin`：列出各时间段的四柱、哪几柱不变、哪几柱会变以及会变的柱牵动哪些结论（日柱变则日主和全部十神都变，要分别解读）；同一天内的范围仍可用个人运势入口的 `birth_time_range`。不要按「哪张更像」替用户选定时辰。

跨日期入口的候选为当地公历分钟 `YYYY-MM-DDTHH:MM`，出生地时区在 `birth.timezone` 指明，重复钟点另给 `birth.fold: 0/1`。带 offset、Z 或秒的字符串会被拒绝。范围端点包含在内，最长72小时；跨时区偏移变化、跳时或未指定 fold 的重复钟点时，按提示拆开提交，不能丢掉 offset 后继续排。同柱只代表干支相同，十神等依赖日主的结论仍须重核，起运也可能在段内变化。

用户更正资料时用 `scripts/birth_correction.py --stdin`，before、after 各自保留明确的年月日、性别和已确认的可选设置，未知时辰可省略。两侧都验证后才比较。农历正月份加 `leap:true` 规范为负月份；负月份与显式 `leap:false` 冲突，公历不接受闰月标记。按 `invalidated` 重核旧结论，并用返回的 `input` 回放，不以默认生日补缺。

出生地同名时（如「朝阳」可指北京朝阳区或辽宁朝阳市），排盘工具返回 `ambiguous_city` 与 `candidates`，照列候选请用户补省份或市名，不替用户挑；「北京朝阳区」「辽宁朝阳」「南京鼓楼区」这类写法可直接解析，区县经度借所属地级市。未收录的地名返回相近候选，仍须用户确认或改给经度。

只知道四柱、想反查出生日期时用 `scripts/pillars_to_dates.py`：先按五虎遁、五鼠遁核四柱本身成立，再给年份范围内全部可能的日期与时间窗口；同一组四柱约六十年重现一次，不替用户选是哪一个。交节表是 UTC+8 钟面上的瞬间，时辰窗口是出生地真太阳时，两种坐标不能直接比：交节当天要用户给出生地经度（`--longitude`）才能把窗口切开，没给时整段列出并标 `depends_on_longitude`，同时给交节的 UTC+8 时刻。子时按时干分早晚：时干属当天日干的只给早子时（零点到一点），属次日日干的只给晚子时（二十三点到零点，日柱仍记当天）。

普通排盘输入不落盘，脚本不主动保存生辰；只有调用方显式给 `--report` 或 `--facts-out` 时，才写到它指定的那个路径。用户确认保存时，由 `personal_profiles.py save --confirmed` 单独写入本机技能目录之外；它与普通计算分开，支持查看、修订和删除。优先通过 stdin 传入私密资料，不写入仓库、发行包或测试样例。旧入口的命令行参数可能出现在进程列表和 shell 历史里。宿主对话记录由对应宿主管理，删除个人档案不等于删除宿主记录。按 [输出契约](22-output-contract.md) 撰写正文。

古籍补查另用 research_session.py 保存通用来源和检索记录到外部 research 目录，不保存个人盘面或整段问答；普通排盘不会调用这个写入入口。个人档案保存仍须用户明确确认。

预测跟踪是另一个显式保存入口：用户授权后，`prediction_log.py` 仅在仓库外保存匿名验证记录，见 [前瞻验证](28-prospective-validation.md)。普通排盘不自动调用；不把姓名、生辰或整段对话复制进记录。

## 运行环境

只需 Python 3.9 或以上，不用安装任何包，计算不联网：排盘用的 lunar_python 和时区数据 tzdata 已随包放在 `scripts/`。本文命令里的 `python` 指本机能用的那一个：依次试 `python3`、`python`、Windows 的 `py -3`，用 `--version` 确认是 3.9 以上。

一个都没有时，先征得用户同意再装 Python：Windows `winget install -e --id Python.Python.3.12`；macOS `xcode-select --install`（命令行工具自带 python3）；Linux 用发行版的包管理器装 `python3`。不要往用户的 Python 里用 pip 装任何东西。装好后或任何工具报环境错误（缺包、时区、编码、古籍文件）时运行 `python scripts/doctor.py`：`healthy=true` 即可用；否则按 `next_step` 处理第一项失败，不要猜原因。

`ok=false` 时处理 message。`reliable=false`、`boundary`、`missing_in_table`、`*_granularity` 等仅解释会改变本题的限制。`hour_known=false` 不能使用内部占位时辰，其他柱也可能因边界待定。

只有要复核旧算法或计算细节才用 `bazi_calc.py`。其 `--no-shensha / --no-geju / --no-yongshen` 是诊断裁剪参数。工程旺衰、格局候选和调候候选不属于默认判词。`--as-of-year` 固定流年参考年，不改变出生盘。

涉及医疗、投资、法律、人身伤害或急性危机，读 [边界说明](20-disclaimer.md) 并提供现实帮助。古籍中的疾病、夭寿、刑克可解释历史语境，不据此诊断个人、预测死亡或下交易指令。
