# 八字核心与使用可靠性：2026-10-26 实施验收

依据：用户确认的竞争研究与优化方案（工作区 `research/competitive-audit-20261024`），基线 v5.9.1 / `81a980a5707505468a10f596f1f19c9088457a9e`。本轮实施，不是完整远期路线图，也不是预测有效性认证。

## 本轮交付

1. 接入《子平真诠》印、食神、七杀、阳刃、建禄月劫的取运章，与已有官、财、伤组成八家。每条保存冻结段落、校验值、可计算前提、解释性条件和例外。没有可计算标准的身强弱、格局成立、合化与救应不自动判定。
2. 在默认八字解读里增加成败救应和变化的结构核对。列已见条件、排除条件、缺失资料、尚待解释条件及原文；本格、变格、兼格候选不自动定为唯一格局。
3. 修复明确点名方法、知识解释、多法和大运问题的路由。提供紧凑结果与按需详解，短答不丢未判、冲突和出处。可选保存本地报告，不自动落盘个人资料。
4. 验证源规则、真实CLI、离线发行包及真实宿主任务；记录可用性、调用与回答问题，不把程序测试冒充实际宿主成绩。

## 已授权的测试接口

- `assess_luck`、格局核对公共接口：规则适用、例外、反例与未知；不认证命理预测。
- `prepare_reading` 及 `bazi_reading.py` CLI：同输入的事实、详简视图、条件和引用一致；输出保存为显式动作。
- `question_router.route` 与 CLI：从自然问法到正确方法/必要资料；知识问题不索取生辰，多法不合成分数。
- 实际 Codex/Claude Code：合成数据、固定请求时间、独立会话、有界轮数/时间/成本。工具不存在或鉴权/配额失败记未运行，不伪造通过。

## 验收门槛

每个新增规则有正例、反例或不适用、未知条件及引用校验。固定输入不得产生新的盘面或来源错误。全量 pytest（包括 slow）、ruff、mypy、古籍验证、开发包冒烟通过；版本/来源固定，旧测成绩不继承。紧凑输出与基线同任务比较体积、保留字段与完整详情可达性。真实宿主的未判保留、无重复采集、工具调用和结论忠实度单列。

保留 Python 3.9+、随包依赖、IANA/DST/真太阳时/交节瞬间、未知时辰和默认不保存资料。研究仓只作对照，不复制其代码或不同许可内容。没有提交、推送或正式发布授权。
