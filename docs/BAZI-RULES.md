# 八家条款如何使用

默认入口 bazi_reading.py 的 schema 2.0 包含八家候选与 25 条核查路径：正官、财、印、食神、七杀、伤官、阳刃、建禄月劫。它们来自所选《子平真诠》对应专章，按月令取用、成败救应与变化章节一起阅读。

这表示已整理 25 条路径，不是只凭八字就能自动裁定全部古法。它也不覆盖所有特殊格局、所有岁运用法或其他书的全部体系。

## 条件分工

程序核可计算的盘面事实，解释者核作用关系：

- 已给的四柱是否完整，某字在何处，某十神是否明透或藏在支中，都可查实。规则分别注明“存在”与“透出”，不能互换。
- 月令取用、合局是否改变结构、根气强弱、位置是否相碍、制化与救应是否有效，需要读完整原文后给理由。未核前保持 unknown。
- met / not_met / unknown 分别指成立、不成立、尚未核实。某一路条件不成立只排除该路，不排除整家。
- 本气、透干、会支形成的候选可能并存，不自动选第一项为最终格局。
- 未知时辰不能证明全盘“没有某字”，边界不固定的日柱也不能据占位日干定十神。

资料足够时，本轮应完成相关解释条件，说明判断和依据，而非原样转交所有 unknown。

## 原文和例外

每条路径有固定 passage_id、短引文、条件、例外段落和适用范围。evidence_bundle 将所需完整段落合并，书章元数据只出现一次；不会为了节省 token 删除救应句。

共同证据包括《论十干合而不合》《论用神成败救应》《论用神变化》；候选家附其专章。日主自身之合、合而不合、兼格等不能一概套“见合就去”。

引用保持原字，正文、注文和项目条件归纳分开。注册表核过的是冻结转录中的原句；facsimile_checked 只有实际逐页核过对应影像才可标记。

## 审核记录

reading_support.py 对八家规则重新计算可计算条件。解释条件若改为 met 或 not_met，须带 condition_evidence：

```json
{
  "condition_evidence": {
    "实际条件ID": {
      "reason": "结合本题盘面和该段例外的具体解释",
      "facts": [{"path": "four_pillars.month.branch", "value": "实际月支"}],
      "passage_ids": ["对应的真实段落ID"]
    }
  }
}
```

该示意不是可直接通过的个人记录。审核器拒绝伪造盘面值、错引文及模型擅改可计算状态，但不能认证理由文字是否正确，最终仍需对照实际回答审查。

测试包含独立原典命例与近似反例，以及未知时辰和伪造条件检查。原典命例只核条款适用关系，不据古人官爵故事测现代预测命中率。

## 诊断接口

bazi_calc.py 保留历史工程旺衰和旧格局、调候候选，便于排错。bazi_reading.py 不输出 yong_shen、ge_ju，也不接受三个 no-* 诊断开关。默认解读不为这些旧键二次计算。

起运另明确 lunar_python 的 Yun sect=1。qi_yun.algorithm_sect 与日界 day_boundary_sect 是两个不同参数，不能混称。
