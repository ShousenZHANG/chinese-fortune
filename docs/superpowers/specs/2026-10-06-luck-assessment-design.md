# 大运取运判断（第一批：正官、财、伤官）设计

日期：2026-10-06。依据：GPT 对 v5.3.0 的审计报告（`research/project-audit-20261005-v530/REPORT.md`）第 5 节「整张命盘和大运没有真正决定逐日等级」与第 6 节第 2–3 项；与用户逐段确认的设计。

## 1. 目标与不做的事

**目标。** 让整张命盘和大运进入个人时段回答：对当前（及下一步）大运，按《子平真诠》的取运原文，给出这步运的天干、地支对本人是喜、是忌、不碍、看条件还是原文没提，每个结论带原句。

**粒度。** 取运原文只讲十年大运，没有逐日规则。按审计报告第 5 节（「某条本命或大运原文若没有逐日含义，不得为填满七天表而降格套用」）和 `references/22-output-contract.md` 第 68 行，这一层是**十年一个结论**；逐日等级照旧按《协纪辨方书》相主（生年），两层分开写。

**第一批范围。** 正官（`ziping:c032`）、财（`ziping:c034`）、伤官（`ziping:c042`）三章取运，加《论行运》（`ziping:c025`）中能计算的通则。用户本人的盘（庚日子月，伤官格候选）在范围内。

**不做：**
- 不改逐日相主等级，不做流年。
- 其余五格（印、食神、七杀、阳刃、建禄月劫）不接，回答里明说「这一格的取运章还没接入」。
- 《论行运成格变格》（`ziping:c026`，运把格局变掉）不在本批。
- 不用现有身强弱打分去替原文选「身轻／身旺」分支：那套权重不是古籍里的。
- 不判合化、位置、成败救应是否成立；这些仍是未判的解释条件。

- `predicate` 只用现有 `bazi_rules.evaluate_condition` 已有的 `present_any`、`exposed_any`、`exposed_none`，另加两个可计算的：`combines`（某类透干与另一类透干天干五合）和 `exposed_count_at_least`（某类透干至少 N 个，用于「印绶叠出」）。

- `branches[].kind` 为 `computed` 时带 `predicate`，程序判定；为 `interpretive` 时不判，两边说法都列出。

## 3. 模块：`scripts/luck_assessment.py`

```python
def assess_luck(chart: dict, luck: dict, registry: dict | None = None) -> dict
def luck_paragraph(reading: dict, who: str = '你') -> str
```

- `chart`：`bazi_calc` 的出生盘；`luck`：`{'ganzhi', 'start_year', 'end_year'}`。
- 先用 `bazi_rules.family_candidates(chart)` 取月令候选；只处理 `officer`、`wealth`、`hurt`，其余候选记为 `not_connected`。
- 对每个已接入候选，逐条配法判前提（三态 met / not_met / unknown，时辰未知时透藏不能判为不存在）；前提全 met 的配法为候选配法。
- 对候选配法，按运干、运支的十神逐条匹配 `effects` 和 computed 分支，interpretive 分支原样列出。
- 汇总：同一个字在全部候选配法里结论一致 → 直接给出（「几种可能的配法都算喜」）；不一致 → `mixed`，分列；只在 interpretive 分支里出现 → `conditional`；都没提 → `not_mentioned`。
- 加 N1–N4 备注。

返回：

```json

  "status": "assessed | unavailable",
  "reason": "（unavailable 时）",
  "luck": {"ganzhi": "己酉", "start_year": 2023, "end_year": 2032},
  "families": [{"family_id": "hurt", "title": "伤官", "basis": "月令本气；…", "connected": true}],
  "scenarios": [{"id": "hurt-seal", "title": "伤官佩印", "passage_id": "ziping:c042:p0003", "quote": "…",
                 "premises": [...], "stem": {"char": "己", "role": "正印", "verdicts": [...]},
                 "branch": {"char": "酉", "via": "本气辛", "role": "劫财", "verdicts": [...]}}],
  "summary": {"stem": "favoured", "branch": "conditional"},
  "notes": [{"id": "N3", "passage_id": "ziping:c025:p0010", "text": "…", "state": "met"}],
  "granularity": "ten_year_cycle",
  "limit": "配法按可计算的透藏列为候选；位置、合克、成败是否成立没判；十年一个结论，不细到每天。"

```

## 4. 接入与输出

- `fortune_reading.py`：每个出生资料完整的参与者，对目标窗口内生效的大运（跨两步运就两步）调用 `assess_luck`，挂在 `participants[].luck_reading`；渲染时在逐日相主段落之后加一段 `luck_paragraph`，写明十年一个结论、不改变每天的等级。
- `bazi_reading.py`：问题含大运、运势、这几年、今年等词时，对当前和下一步大运各调用一次，挂在结果的 `luck_reading`，渲染一段。
- 示例（用户本人盘，己酉运）：「你现在走的己酉运（2023–2032）。按《子平真诠》伤官取运：你的盘按能算的透藏有三种可能的配法——伤官佩印、伤官带煞、伤官用官，对『己』（正印）三种都算喜（「印運亦吉」「喜印忌財」「運喜財印」）；对『酉』（本气辛，劫财），只有伤官用官一句「若局中官露而財印兩旺，則比劫傷官，未始非吉」，要看财印是否两旺，这里没判。你的盘到底按哪种配法成立，还要看位置和合克，原文没给可计算的标准。这是十年一个说法，不细到每天；上面的逐日吉凶仍按出生年相主。」

## 5. 出错处理

| 情况 | 输出 |
|---|---|
| 出生时辰未知 | `unavailable`：透藏判不全，不给 |
| 交节附近、月令未定 | `unavailable`：月令没定 |
| 大运未算出（起运资料缺） | `unavailable`：大运没算出 |
| 已接入格但没有候选配法 | `assessed`，说明「你的盘不属于已接入的配法」 |
| 月令属其余五格 | `assessed`，`connected: false`，说明这一格的取运章还没接入 |

原文保护：每条配法记 `passage_id`、`quote`、`sha256`；`quote` 必须出现在冻结原文里、哈希一致，否则测试失败，须重新审定。

## 6. 测试（先写测试）

1. **数据完整性**：三章除总论句（c032 p0001、p0007，c034 p0001，c042 p0001）外，每一段都有对应配法或分支；`words` 是 `quote` 子串；十神名只用十个合法值；哈希与冻结原文一致。
2. **原典例子**：《论行运》p0006「丙生子月亥年……逢巳午則相沖」→ 巳冲亥（年）、午冲子（月）均为急；p0008「丁生亥月，而年透壬官」→ 运干天干分开判。能对上的结论与原文一致。
3. **用户本人盘**：丁丑 壬子 庚子 丙戌、己酉运 → 候选配法含伤官佩印、伤官带煞、伤官用官；`summary.stem == 'favoured'`，`summary.branch == 'conditional'`。
4. **分支计算**：正官带煞的劫合煞、伤官合煞各一个正反例；印绶叠出；财旺生官的复透印、带食破局。
5. **边界**：时辰未知、月令未定、大运缺失、候选冲突（mixed）、其余五格（not_connected）、冲日时为缓。
6. **端到端**：运势回答与八字回答出现大运段，逐日等级不变；发布包冒烟加一项。

## 8. 风险

- 「配法」以透藏判候选，会出现多个候选；输出靠「一致才直说、不一致分列」控制，不替用户挑。
- 「身轻／身旺」等未判分支多，部分大运的结论会是「看条件」；这是原文本身的条件，照实说。
- 地支按本气取十神是通行读法，原文没逐字规定；输出注明。
