# 直接回答：自然白话与证据一致

本文只决定怎样表达；可下什么结论由盘面、适用条件和证据决定。与其他指引冲突时，以证据范围为准。条款分歧按 [裁决顺序](26-precedence.md) 处理。

## 首答

默认约300–600字，简单问题更短，详解按需展开。使用日常完整短句，像对人解释一件具体事情；不写文言碎句，不让用户先学会术语才看懂答案。

1. 先回答本题：支持的判断、实际选择或需要的一次补问。说明最主要原因。
2. 只引用必要的古籍短句和出处；每段引文后立即解释原义、用户的对应条件及为什么适用于本题。
3. 只说明会影响本次结论的分歧。缺哪项只暂停依赖它的判断，其余部分继续答。

第一段独立可读。术语放在后面并当场解释。不要用另一个术语解释术语。表达自然比凑满字数更重要。

续问补齐信息后给最终选择，同样保留必要的原文和紧跟的解释。无需重复整张盘，但要让这次回答单独可读：读者能分清实际排序理由与古法能够支持的范围。只有补问信息、尚未作判断时，可以先简洁问清。

## 首句按问句类型切

| 用户问 | 首句 | 例 |
|---|---|---|
| 怎么样、如何、好不好 | **结论** | oct14 需要避开：覆盖到辛酉日，是秋季的天转日，《渊海子平》说这天忌出行。 |
| 该不该、选哪个、哪天、几点 | **动作** | 首选 oct13：10月13日 9:00–11:00（上海时间）。 |
| 行不行、可以吗、是不是、有没有 | **是／否** | 不行。／可以：……／不建议。／古籍没有这条。 |

首句之上不许有任何东西：表格、代码块、卦名、四柱串、`审核 0 错`、版本号，一律放在它下面。`fortune_reading.py --markdown` 按同一张表切首句（`_question_kind`）；宿主自己组织回答时也照此办理。

首句写具体的候选、日期、钟点和条款，不写换一题也成立的句子。被条款排除的候选在首句点名，冲突时给出窗口名和具体钟点；首选所在窗口里有忌时，首句加一句「别把时间挪进 11:41–13:00（午时）」。只有需要用户补输入时，才可以用固定问句。

## 限制句判据

摘要里的限制句必须是本题独有的。判据只有一条：

> 这句话换到别的卦、别的年、别的颜色上，还成立吗？
> **成立 → 套话 → 删。**

| 句子 | 换一题还成立？ | 判 |
|---|---|---|
| 好不等于稳 | 成立 | 删 |
| 这只能当参考 | 成立 | 删 |
| 单看日期未触犯规则，不能消除时段疑问 | 成立 | 删 |
| 不能只看到“财”“官”就认定会收到钱或录用 | 成立（与多数问题无关） | 删 |
| 别把时间挪进 11:41–13:00（午时），那是庚申日截路空亡的忌时 | 不成立（这个窗口独有） | 留 |
| 癸亥日的子时、丑时只有《渊海子平》算作忌时，《三命通会》不算 | 不成立（这一天独有） | 留 |
| 身弱这个判定是通行推法，不是古籍明文 | 不成立（这盘独有） | 留 |

## 时间选择

读取 `conclusion`、`recommendation` 和 `practical_choice`。它们分别保留判断范围与实际排期依据。

- `practical_choice`：可以明确给首选和备选，包含日期、起止时间、时区；说明它依据用户的空闲时间和已给偏好。具体分钟由现实排期确定，不能说是古籍算出的最佳分钟。
- `screened_only`：仅说明已检查的通用规则没有排除该窗口；没有完成个人吉凶排序。
- `clause_conflict`：点明哪条规则或哪两个版本影响本次时间，先保留可核事实。
- `tied_no_clause_separates`：已查条款未分出高下，不扩大成所有古法或所有个人条件都相等。若缺实际偏好，一次问清尽早、尽晚或候选顺序。
- `preferences_required`：可行安排超过一个，缺实际取舍偏好；`practical_tie`：已有偏好仍分不开。都保留候选，不按输入顺序偷偷挑一个。
- 真正的个人古法排名必须有完整适用依据；通用忌日、出生年生肖、条款数量、黄历吉字都不能替代。

示例仅演示表达：

> 按你说的“尽早安排”，首选10月13日9:00–10:00，备选10月15日9:00–10:00，都按上海时间。这样能满足你的一小时时长要求。这个顺序来自你的档期偏好；当前古籍规则没有完成对你个人的吉凶排序。

只有实际输入与结果符合时才能使用这些日期和理由。单个候选也可以给具体可行时间，但不能称它比其他未比较的时间更好。

## 原文与白话

摘句保留必要的否定、条件和例外。随后自然解释：这句话在说什么，你的哪些已确认信息与它对应，哪些只是现代场景解释。原文不占主体。

查询调候时先运行 `python scripts/classical_search.py --climate-key "庚|子"`（替换为本人已固定日主、月支），通过已核定位读取当月专段；查看 `witnesses` 和 `quality_notes`。未知日主/月支先分别核对候选。

五行与颜色的传统对应可以解释，但不据此推荐购买某颜色能改变结果。也不能数哪种颜色获得更多条款便排出高下。

## 资料不足时继续做什么

先给已有依据支持的部分，再按 [限时补查](25-classical-research.md#限时补查与候选库) 补查约5分钟。本库零命中只表示这些版本和检索词未找到，不代表全部古籍不存在。已经具备盘面和原文时，完成条件核查，不循环说“还需要分析”。

只有 `evidence_needed`、`screened_only` 两种状态以「可继续补查约5分钟」收尾；已经给出首选、排除或冲突结论的回答不加这句。

## 禁用词

### 甲类 · 禁用（删了零信息损失）

出现在任何位置都算错。带 `← 正则` 标注的那条按正则比对，其余按字面比对。

```
仅供参考 | 只能当参考 | 参考而已 | 姑且听之 | 信不信由你
要说清楚的是 | 必须说清 | 先说清楚 | 说句实在的 | 老实说 | 说点真的
好不等于 | 不等于保证 | 不会自己变好 | 不会改变什么
我理解你想听什么
我看到的不是……是            ← 正则 /我看到的不是[^。！？]{0,24}[，,]\s*是/
```

会话末尾的整段文化参考声明**一次即可**，见 [输出契约](22-output-contract.md)「一次说明文化参考性质即可」那条。重复出现记为甲类。

### 乙类 · 限位（有信息，只许在层 2）

**出现在摘要段（首个空行之前）算错**，出现在层 2 不拦。

```
给不了 | 答不上 | 排不出来 | 算不了     ← 后面必须紧跟「因为」
两书相反 | 起法分歧 | 两说并列
passage_id | precedence_version         ← 指裸字段名进摘要
transcription_status | facsimile_status
```

`passage_id` 进乙类指的是**字段名出现在白话里**，与下面核对单「排名有没有 `passage_id`」不冲突：后者要求层 2 有出处，前者禁止把键名当白话。

**例外**：「古籍没有这条」**本身就是答案**时，允许且应当出现在首句。检查时先把这一句剥掉再扫其余部分，免得一句缺载声明替后面的并列话术挡枪。

### 保留（不许删）

以下**不进甲类，在摘要段也不拦**；删了就是隐瞒：

- 通过上节判据、本题独有的限制
- 输家条款那一行「另说：……」，见 [裁决顺序](26-precedence.md)
- 条款前提不成立的说明
- 转录状态标注（在层 2）

## 发出前核对

- [ ] 首句是不是按问句类型给了结论、动作或是否？
- [ ] 首句有没有写出具体候选、日期、钟点，而不是换一题也成立的句子？
- [ ] 那句限制换个题还成立吗？成立就删。
- [ ] 甲类词一个都没有？乙类词有没有跑进摘要段？
- [ ] 是否真正用了所称的个人信息；首选时间与条件是否一致？
- [ ] 排名有没有 `passage_id`？没有就不许排。只按档期偏好排的，有没有说明不是古法排序？
- [ ] 每段引文后是否有能独立看懂的解释？输家条款那行留了没有？
- [ ] 分歧是否使前面的结论失效？

程序通过只证明其检查范围，正文仍需逐句核对。本仓库外有一个可选的 Stop hook（`~/.claude/hooks/format-check.js`，**不随本包发布**），它在答案发出之后才触发，只能改善下一轮；上面这份核对单才是实时生效的那一层。

## 明确判断与方法分歧

解读前固定主方法及版本，不因结果不讨喜而换方法、重复起卦。每个个人判断核对：实际输入字段 → 原文成立条件 → 例外 → 本题时间粒度 → 结论。改出生信息后重新核查；条件相同可以结论相同，不制造虚假的个性化。

原文相反时比较上下文、适用范围、例外和版本；只有可指出依据的差异才能消解分歧。否则直接说“这两条依据在本题上冲突，无法据此定出首选”，继续回答不受影响的部分。不能按支持条数投票。依据不足时限时补查，仍不足就说明无法判断具体事件；不把“可能”当作推导。明确的传统解释不等于现实保证。

需要检验事后结果时按 [前瞻验证](28-prospective-validation.md)，不能把已知经历算成预测命中。
