# 紫微斗数：盘面、条件与解释

用户明确点名紫微时使用。遵循[输出契约](22-output-contract.md)；先完成与问题有关的盘面分析，再说明限制。紫微使用独立的宫位、安星及四化方法，不给默认八字结论投票。

## 一、一次排盘后的工作

1. 核对公历/农历、闰月、出生时间、出生地与换日口径。问今年时先取得用户当前所在地时间；指定流年则明确记录该年。出生时辰不明时只解释方法，不任造完整命盘。
2. 运行 `python scripts/ziwei_calc.py --help` 确认参数。正常完整解读保留主星、辅星、四化和三方四正；只有用户问盘面骨架时才用 `--brief-palaces`。
3. 从问题选相关宫位，说明该宫的主辅星、对宫、两个三合宫及四化落点。空宫的借星须标为借宫，不变成原坐守星。问某一方面（夫妻、婚姻、事业、财运、健康、出行、房产等）时加 `--focus-palace 夫妻`：`focus` 给该宫主星与亮度、借宫、对宫与三合、本宫生年四化、吉煞与相关格局，`quotes` 是讲该星的《全书》段落里提到该宫的那一句（原字照录，可直接引用；很多星没有这样的句子，就是空的），`search_queries` 是继续查原文的检索词（`classical_search.py --book ziwei --query "天机 夫妻"`），`answer_order` 是分条顺序。结构可以照用，断语不能从结构推出：每颗星取到原文再白话解释，查不到原文的星只说位置。
4. 对每个格局说明 `required`、`bonus`、`breaking` 三组条件；`breaking` 有内容时与成格条件一起说。格名不是优劣等级。
5. 给出已能支持的结构结论。若只能完成盘面说明，明确缺的是哪条解释依据，保留完整盘面回答，不能把未核条款补写成个人结论。

输出的 `say` 是可以照抄的盘面句子：命宫与主星亮度、身宫、五行局、命主身主、生年四化各落哪宫、命中的格局及其出处和减力条件、本次排盘口径。照抄，不自己改写宫位或四化。`self_check` 用安星规则之间的互相约束复核这张盘，`checked` 列出核过的项，`failed` 只列没过的项和原因（14 主星各一次、紫微天府以寅申为轴对称、十二宫逆排、宫干合五虎遁、命宫合寅起正月公式、身宫只落六宫之一、擎羊陀罗在禄存前后、生年四化星都在盘上）；`ok` 为 false 时不要用这张盘回答，先报告哪一项没过。

白话顺序（在[输出契约](22-output-contract.md) 第 4 节要求的开头直答**之下**展开，不取代它；开头仍须先给结论、原因与本题最关键的限制）：本次看到什么 → 为什么这样判断 → 哪个条件会改变判断。普通正文不堆内部字段或十几个星名。

按需裁剪：`--no-da-xian` 省略大限，`--no-patterns` 省略组合候选，`--no-sihua` 省略各宫自化（保留生年及岁限四化）。仅在用户只查原局位置或盘面骨架时使用；完整解读保留相关数据，不能先裁掉再凭空补解释。

`--brief-palaces` 同时只附基础条款索引；完整原句、条件与来源可用 `python scripts/method_rules.py --method ziwei` 查询。正常完整排盘直接附已去重的来源及应用记录，未核条件仍保持待核。

## 二、十二宫与身宫

十二宫是传统分析的主题目录。宫名不提供现实事实；例如财帛宫不是收入数据，夫妻宫不是伴侣行为证据，疾厄宫不是医学指标。

| 宫位 | 本次可组织的主题 |
|---|---|
| 命宫 | 全盘起点及与三方四正的关系 |
| 兄弟宫 | 手足、平辈关系的传统主题 |
| 夫妻宫 | 亲密关系的传统主题 |
| 子女宫 | 子女、晚辈的传统主题 |
| 财帛宫 | 财务主题的星曜与四化位置 |
| 疾厄宫 | 相应宫位与历史用语说明；不作健康判断 |
| 迁移宫 | 外出与环境变化的传统主题 |
| 仆役宫（交友宫） | 合作、交往的传统主题 |
| 官禄宫（事业宫） | 职业主题的星曜与四化位置 |
| 田宅宫 | 居所主题的星曜与四化位置 |
| 福德宫 | 休闲、生活取向的传统主题 |
| 父母宫 | 长辈主题的星曜与四化位置 |

身宫叠在命、夫妻、财帛、迁移、官禄、福德之一，并非第十三宫。项目从寅宫起正月，顺数到生月，再逆数时辰安命、顺数时辰安身。十二宫从命宫依次逆排。这个结构可以复算，不能据此把某年龄或某领域定成人生必然重心。

宫位地址写作子宫、丑宫、寅宫、卯宫、辰宫、巳宫、午宫、未宫、申宫、酉宫、戌宫、亥宫，与命宫等主题宫名分开。仆役宫、奴仆宫、交友宫为相关历史别称，脚本采用奴仆宫。

手工推导仅在用户询问起法或做排盘研究时读 [02-ziwei-paipan.md](02-ziwei-paipan.md)。运行失败须先修输入或依赖，不改用未经检查的心算填满命盘。

## 三、来源与流派状态

《紫微斗数全书》卷二[固定转录版本 1963110](https://zh.wikisource.org/w/index.php?title=紫微斗數全書/卷二&oldid=1963110)包含安身命例、安十二宫例、安星诀与「一命宫」亮度文字。本项目未校原刻影像。

项目表并非逐项照抄这一转录：魁钺辛干、丙丁口诀及壬干四化等存在异文或取表差异；闰月处理也须看输出说明。应报告当前选择，不称所有流派共识。

`self_transformations` 是以宫干查四化，所化星就在本宫时标记自化。标签有自化禄、自化权、自化科、自化忌。它与生年四化不同，属于本项目采用的后起飞星概念；当前未给出独立核定的自化解释条款。离心、向心也只是飞化方向标签。按三合法读盘时可略过这部分，不把它归到《全书》已核原文。

## 六、四化及岁限

生年四化用生年干，大限四化用大限宫干，流年四化用指定流年干。层次分开呈现；同字出现多次不等于效力倍增。

| 乙 | 天机 | 天梁 | 紫微 | 太阴 |
| 丙 | 天同 | 天机 | 文昌 | 廉贞 |
| 丁 | 太阴 | 天同 | 天机 | 巨门 |
| 戊 | 贪狼 | 太阴 | 右弼 | 天机 |
| 己 | 武曲 | 贪狼 | 天梁 | 文曲 |
| 庚 | 太阳 | 武曲 | 太阴 | 天同 |
| 辛 | 巨门 | 太阳 | 文曲 | 文昌 |
| 壬 | 天梁 | 紫微 | 左辅 | 武曲 |
| 癸 | 破军 | 巨门 | 太阴 | 贪狼 |

这张表与项目所选四化表对应；例如壬干取左辅化科，与上列转录的天府记载不同。禄、权、科、忌可作传统条件检索词，不能直接翻译成钱、职位、录取或灾祸。

大限以水二、木三、金四、土五、火六局决定起始岁数；阳男阴女顺行、阴男阳女逆行。结果是岁段与宫位对应，不是这十年内一定发生的事。问某月、某日或某时辰时，用 `ziwei_calc.py ... --horoscope-date YYYY-MM-DD [--horoscope-time HH:MM]`：`horoscope` 按安斗君诀（ziwei:c002:p0064）给出流年斗君，再顺推流月、流日、流时各落哪一宫，以及该层天干的四化星。`--year-divide` 同时控制本命和目标流年；流年四化、宫位、流曜、斗君与五虎遁月干跟随选定年干支。原始农历日期、农历月序和虚岁另按输出约定保留。只给日期时披露正午代表时刻。原书只直接载斗君起法，流月顺行、流日、流时是现代通行口径。与其他软件对照时分别核晚子时、年界和月干口径；本项目 `--sect 2` 流时时干按次日，iztro默认按当日，exact年界模式的月干也可能因农历月与节月不同而异。没传日期时不要从本命 `dou_jun` 自己推流月、流日。

每层还有 `stars`：运（大限）、流（流年）、月、日、时五层各按该层天干安禄、羊、陀、魁、钺、昌、曲，按该层地支安马、鸾、喜，流年另有年解。每个活动层的 `twelve_gods` 随本层干支的地支安将前、岁前十二神，依据固定 [Renhuai现代软件实现](https://github.com/Renhuai123/ziwei-doushu/blob/495b79ecb3524b20b2edc026067d7d0b0f407319/lib/ziwei/shier-shen.ts)，不是所选《全书》的直接安法。其第七岁前标签写岁破，本项目保留大耗兼容名称，输出披露位置命名差异，不据此合并不同体系的同名星。`horoscope.da_xian` 按目标农历年减出生农历年加一的虚岁选择，`age_basis` 明示正月初一；未到第一个大限时为 null，未请求流时也为 null。流曜和十二神分别读取，不自行解释成现实事件。

宫位落点只是“这一层落在本命哪一宫、哪些星化禄化忌”，不是当天会发生的事；解释仍按本命宫星和原文条件，不把流日化忌说成当天出事。

## 六之二、十二神、亮度与流派设置

每宫的 `twelve_gods` 给四组十二神，出处见输出的 `twelve_gods_sources`：

- 长生十二神（起点出自《全书》卷二 ziwei:c002:p0057：火局寅、木局亥、水局申、金局巳、土局申起长生；顺逆用现代通行的阳男阴女顺、阴男阳女逆，与 ziwei:c002:p0056 字面“男命顺数、女命逆数”不同，回答里要说明）：长生、沐浴、冠带、临官、帝旺、衰、病、死、墓、绝、胎、养。
- 博士十二神（现代通行口径，随禄存起，顺逆同上；所选转录未载）：博士、力士、青龙、小耗、将军、奏书、飞廉、喜神、病符、大耗、伏兵、官府。
- 将前十二神（现代通行口径，按年支三合起将星顺行；所选转录未载）：将星、攀鞍、岁驿、息神、华盖、劫煞、灾煞、天煞、指背、咸池、月煞、亡神。
- 岁前十二神（现代通行口径，从年支起岁建顺行；转录 ziwei:c002:p0061 只载丧门、吊客、白虎、官府的相对位置）：岁建、晦气、丧门、贯索、官符、小耗、大耗、龙德、白虎、天德、吊客、病符。

十二神只是宫位上的标签，不单独推出吉凶或事件；名称与神煞同名（如华盖、咸池、天德）时，按这里的起法理解，不与八字神煞混用。

亮度默认用主流排盘通行的七级表（庙、旺、得、利、平、不、陷，与 iztro 2.6.3 默认一致），主星在 `main_stars[].brightness`，辅星和煞星在 `aux_brightness`；没标的格表示该星在此宫不论亮度。旧版四级表用 `--brightness project4`。亮度只展示，不参与安星。

## 七、三方四正与夹宫

三方四正 = 本宫 + 对宫 + 两个三合宫。对宫地支差六位，三合宫各差四位。例如官禄宫在戌，则连同辰、寅、午四宫看。

夹宫是前后相邻两宫，例如命宫子，亥与丑夹命；它不是地支六合。说明星是坐守、会照还是夹宫，不混写位置关系。

## 八、格局

`patterns` 每项给 `name`、`source_status`、`passage_id`、`quote`、`extra_passage_ids`、`reading_note`，以及四组条件：`required`（成格必须）、`bonus`（原文说更好的）、`breaking`（原文说减力或破格的）、`to_check`（`to_check` 收两类原文没说死的地方：一是「吉多」「凶多」这类没给数量的说法，只列见到的星；二是原文用词范围未定，如禄马交驰「忌见杀」的「杀」可指七杀或诸煞，只列同宫见到的，多不多、算不算都不替原文定）。`source_status` 有三种：`quanshu_definition` 条件照《全书》原句拆出，`quote` 可以直接引用；`quanshu_reading` 书中有此格，但原句的范围或读法有歧义，`reading_note` 写明本项目取了哪种读法、没取哪种，回答时要把这句一起说；`modern_convention` 所选转录查不到，只能说是现代通行的说法。`extra_passage_ids` 是加减条件出自的其他段落。格局是盘面结构的名称，不直接推出富贵贫贱、婚姻、健康；`breaking` 或 `to_check` 有内容时要和 `required` 一起说，不能只报成格。

## 九、完成一次相关解释

用户问工作：先报告官禄宫及其三方四正的实际组合，再区分生年与当前岁限；只把找到完整条件的条款用于传统解释。用户已提供岗位、经历时，可据其现实情况讨论行动，不能从星名创造职业适配结论。

用户问感情：解释夫妻宫对应的盘面及适用条件，不从化忌或桃花词判断对方态度、忠诚或结婚次数。

结构示例：若输出“紫微、天府同坐寅宫”，可说“这两颗星在同一宫，因此命中了紫府同宫的组合候选；还要看寅宫在这张盘里是哪一宫，不能先当命宫格局。”这一句已完成组合层判断，不需要补一段吉凶套话。

若另做八字分析，两套结果分别展示规则与分歧。相似措辞不构成彼此验证，更没有自动提高准确率的依据。
